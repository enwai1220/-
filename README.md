# 失败免疫练习 · 事情梳理

本机单用户工作台，使用 Python 标准库、原生 HTML/CSS/JavaScript 和 SQLite。

## 打开

安装 Python 3.11 或更新版本。Windows 双击 `打开失败免疫练习.cmd` 或 `打开事情梳理.cmd`。入口自动检查并启动本机服务。

其他系统可运行：

```sh
python backend/server.py
```

浏览器打开 http://127.0.0.1:3010/ ，点击「事情梳理」Tab，二级入口为 http://127.0.0.1:3010/?page=things 。后端也提供 `/things`。

旧版 3010 服务尚在运行时，Windows 启动器保留它并启动 3011 兼容后台；更新后可继续使用原地址。端口被其他程序占用时提示，不结束未知进程。

## 事情梳理

- 每个非空行视为一件独立任务，同名不同行分别保留，最多 100 件。
- 分析当前全部任务，依目标、影响及长期价值判断重要性，依截止时间和延误后果判断紧急性。缺少信息标记「待确认」。
- 展示四个象限各自的 TOP 3、优先原因及下一步，以及全部任务的分类理由和数量。
- 再次分析替换上一轮结果；失败保留当前输入与最近成功结果。分析时编辑输入不会让旧结果覆盖新任务。
- 点击分析右边的「归档」，将本批输入、完整成功分析与时间写入独立数据库，再清空当前批次。修改后需重新分析才能归档。重试不会重复归档。
- 下方「历史归档」可展开查看以往批次；输入、最近结果和归档可在刷新与服务重启后恢复。

## 数据与备份

- 失败免疫：`data/failure-immunity.sqlite3`。
- 事情梳理：`data/task-triage.sqlite3`，独立存储当前输入、最近成功分析和历史批次。
- 旧版同库的事情梳理状态首次启动自动迁移，保留原表备查；后续启动不会覆盖新库。
- SQLite WAL/FULL，同步事务与版本检查。备份位于 `data/backups/`，事情梳理备份在其 `task-triage/` 子目录；页面底部可导出 JSON。
- 浏览器 localStorage 仅用于草稿恢复；清除浏览器不删除已保存的数据库内容。
- 本仓库只保存源码。个人记录、数据库及备份、日志、环境配置和凭据不上传。GitHub 源码同步不能代替数据备份。

## AI 运行条件

记录与归档保存在本机。AI 分析需要本机已安装并登录 Codex、可用网络以及用户自己的 `~/.codex/config.toml` 模型配置。凭据从用户现有本机登录读取，仅在内存使用，不写入项目或浏览器。

已配置本机 Responses 转发服务时通过 HTTP/SSE 接收结构化结果；其他配置使用 Codex CLI。模型不使用工具，180 秒超时，不自动重试。下载源码不会附带任何账号、密钥或模型服务。

本项目只绑定 127.0.0.1，用于本机单用户；不作为公网服务器。

## 验证

```sh
python -m unittest discover -s tests -v
```

20 项测试覆盖原有记录、逐行解析、重新分析替换、失败保留、版本冲突、独立库迁移、归档原子清空、下一批任务、重复请求与备份恢复。浏览器验收另验证真实 AI、归档历史、刷新恢复及移动端布局。

## 目录

- `frontend/`：两个页面及界面脚本。
- `backend/`：HTTP 接口、两个数据库结构和分析提示词。
- `scripts/`：固定启动入口。
- `tests/`：隔离数据库测试，不访问正式数据。

维护后的源码更新同步到本公开仓库；运行时个人数据留在本机数据库。
